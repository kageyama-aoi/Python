# 00_ランチャー

Python直下の各ツールをまとめて起動できるTkinter製GUIランチャーです。ツール側のコード・依存関係には一切手を入れず、各ツールフォルダに置かれた`launcher.json`マニフェストを読むだけの方式を採用しています。

## 使い方

```bash
python app.py
```

または `run.bat` をダブルクリックする。

起動すると、Python直下を再帰的に走査して`launcher.json`を持つツールを一覧表示し、アクションボタンをクリックすると対応するスクリプトが実行されます。

## launcher.json の書き方

対象ツールのフォルダ直下に置きます。

```json
{
  "name": "表示名",
  "description": "一言説明",
  "actions": [
    {
      "label": "ボタンのラベル",
      "kind": "gui | cli | server | generator",
      "entry": "run.bat",
      "url": "http://127.0.0.1:5000/",
      "open_after": "output/*.xlsx",
      "note": "補足（クリック時に案内ダイアログとして表示）"
    }
  ]
}
```

### kind の意味と挙動

| kind | 意味 | ランチャーの挙動 |
| --- | --- | --- |
| `gui` | Tkinter等のGUIアプリ、起動後ブロッキングで動き続ける | 起動して結果は待たない |
| `cli` | 実行して終了するコンソールアプリ | 新規コンソールウィンドウで起動して結果は待たない |
| `server` | ローカルサーバーを起動するタイプ | 起動して結果は待たない（ブラウザを開く処理は起動スクリプト側に任せる） |
| `generator` | 実行後に成果物ファイルを生成するタイプ | 完了を待ってから`open_after`に一致する最新ファイルを自動で開く |

`url`はserver系の参考情報（ポートが可変の場合は`note`で補足）。`open_after`はgenerator系必須、ツールフォルダ基準の相対globパターンで指定する。

## 前提

- Python 3.x（標準ライブラリのみ、追加インストール不要）
- Windows（`cmd /c`によるバッチファイル起動、`os.startfile`による生成物オープンを利用しているため）

## 既知の制約

- `entry`は起動時にツールフォルダ内の絶対パスに変換してから実行している。日本語を含むフォルダ名では、相対パス＋`cwd`指定の組み合わせだと`cmd.exe`が実行ファイルを見つけられないことがあるため
- 現状はWindows専用（Selenium/Playwright系ツールも含めWindows前提で作られているため、当面はこれで十分と判断）
- `launcher.json`が無いツールはランチャーの一覧に出てこない（今後段階的に追加予定）
