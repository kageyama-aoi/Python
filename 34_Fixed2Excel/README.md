# 34_Fixed2Excel

## 概要
固定長テキスト（1レコード=1行、バイト位置固定のフラットファイル）とExcelを相互変換するツール。

- **固定長 → Excel**: `configs`内の設定Excel（データ/ヘッダー/トレーラー/エンドレコード各シートに開始位置・文字数を定義）を使い、`data/input`の固定長テキストを解析して`data/output`にExcelとして出力する。
- **Excel → 固定長**: `data/output`の（編集済み）Excelを、同じ設定Excelのルールに基づいて固定長テキストへ復元し、`data/recreated_input`に出力する。
- どのファイルにどの設定Excelを適用するかは `data/configs/mapping.csv`（ファイル名に含まれるキーワード ⇔ 設定ファイル名の対応表）で判定する。

設定Excelは1行目=項目名、2行目=開始位置（1始まり）、3行目=文字数 という横並び形式（`データ`/`ヘッダー`/`トレーラー`/`エンドレコード`の4シート、データ以外は無くてもよい）。実際の固定長ファイルは1ファイル内で全レコード種別の総バイト数が揃っているのが一般的（テキストエディタで開いたときに各行の桁が揃って見える）なので、サンプルも4種別とも80バイトに統一し、末尾を「予備」フィラーで空白埋めしている。エンドレコードはファイル終端を示すマーカーとして区分コード以外ほぼ空白のみ、という構成にも対応する。
**`データ`シートだけの設定でも動作する**（ヘッダー/トレーラー/エンドレコードの識別レコードを持たない、全行が同一形式の単純な固定長ファイルを扱う場合に、他のシートを用意する必要はない。全行が「データ」として解析・復元される）。
レコード種別は各行の先頭1バイトで判定する（`config/main.yaml`の`record_type_codes`で変更可。サンプルはヘッダー=1、データ=既定（該当コード無し）、トレーラー=8、エンドレコード=9）。
出力Excelの「区分」列には先頭1バイトの生コードをそのまま保持しており、Excel→固定長復元時にこの値で先頭バイトを書き戻す（値を消すとその行は復元時に空白バイトになる）。

出力Excelは1行目=項目名、2行目=開始位置（1始まり）、3行目=文字数、4行目以降=実データという構成にする（設定Excel自体と同じ並び）。開始位置・文字数はヘッダー行のコメントとしても併記する。同じ項目名が複数のレコード種別で使われる場合（例:「予備」フィラーがヘッダー/データ/トレーラー/エンドレコードそれぞれにある）、開始位置・文字数が種別ごとに異なることがあり1列に混在できないため、「項目名（種別）」の形で種別ごとに別カラムとして分けて出力する（例:「予備（ヘッダー）」「予備（データ）」）。Excel→固定長復元時は2,3行目（開始位置・文字数の参考表示）を実データとして読み込まないよう自動的に読み飛ばす。

出力Excelは見やすさのため以下も自動付与する：列幅を内容に合わせて自動調整、レコード種別（ヘッダー/データ/トレーラー/エンドレコード）ごとの行の背景色分け、全セルへの罫線、同じレコード種別が2行/2列以上連続する部分の行・列グループ化（Excelのアウトライン機能で折りたたみ可能）。列グループは項目ブロックが隙間なく隣接すると1つの範囲に融合してしまうため、ブロックの境目に薄い区切り列（グレー背景・幅3）を自動挿入し、種別ごとに独立して開閉できるようにしている（復元時はこの区切り列を無視する）。データ行のセルは編集時の先頭ゼロ消失（"000"→"001"と打ち直すと"1"になる罠）を防ぐため文字列書式（@）に固定している。

## 実行

### GUI（推奨）
```bash
python src/gui.py
```
よく使う **固定長テキスト → Excel 変換** / **Excel → 固定長テキスト 復元（＋差分チェック）** / **差分チェック（入力 vs 復元後）のみ** は上部に大きめのボタンで配置。
「復元」ボタンは復元完了後にそのまま差分チェックまで自動実行し、往復（固定長→Excel編集→固定長復元）で意図しない変化が起きていないかを1アクションで確認できる。差分チェックだけを回したいときは3つ目のボタンを使う。
「新しい種類のファイルに対応する」の **新しいファイルに対応** / **mapping.csv 編集**、および **環境初期化** は下部にまとめてある。ログはウィンドウ内に色分け表示される。

GUIはTkinter標準ライブラリのみで動作し、`sv-ttk` / `pywinstyles` は任意（`pip install sv-ttk pywinstyles`で入れるとWindows 11スタイルのダークテーマ・タイトルバーになる。未インストールでも標準ttkテーマで正常動作する）。

#### 新しい種類のファイルへの対応（GUI）

**新しいファイルに対応** ボタンでウィザードを開くと、次の流れを1画面で完結できる：
1. `data/input/` に置いた対象ファイルを選択（設定ファイル名 `config_<ファイル名>` を自動提案）
2. 仕様書の桁位置の表を貼り付け（1行 = `項目名<TAB>開始位置<TAB>文字数`、開始位置・文字数は1始まり）。「データ」タブは必須、ヘッダー/トレーラー/エンドレコードのタブは形式に無ければ空でよい
3. 「プレビュー」で項目一覧・開始/終了位置を確認し、桁の重なり・隙間・レコード長ズレを警告表示
4. 「作成して変換する」で `data/configs/config_<名前>.xlsx` を生成 ＋ `mapping.csv` に行を追加 ＋ そのまま変換を実行

**mapping.csv 編集**ボタンでは、現在の登録一覧（キーワード/設定ファイル名/備考）を表と一緒に確認しながら、
`data/input`・`data/configs`内のファイルをプルダウンから選んで組み合わせを個別に登録・削除できる
（inputファイルを選ぶとキーワード欄にファイル名（拡張子除く）が自動入力される。手で書き換えも可能）。
「inputをスキャンして候補追加」ボタンで、未登録の新規ファイル名からキーワード候補を一括追記できる（旧「mapping.csv 更新」ボタン相当。設定ファイル名は一覧で手動確認）。
登録・削除のたびに既存のmapping.csvを自動でタイムスタンプ付きバックアップする。
既存キーワードへの登録で適用Configが変わる場合は上書き確認ダイアログを出す。

**フォルダを開く**の4ボタン（設定/入力/出力/復元後）は、対応する`data/`配下のフォルダをエクスプローラーで直接開く。
処理中でも押せる（読み取り専用の操作のため無効化対象に入れていない）。

ログはレベル（INFO/WARNING/ERROR）に加え、一連の処理の開始/終了（青/緑）、差分チェックの項目単位の差分detail行（紫）を色分けして表示する。

### CUI
```bash
python src/main.py
```
メニュー番号を入力して選択する。

操作内容：

1. **環境初期化** — `data/configs` `data/input` `data/output` `data/recreated_input` を作成し、サンプル設定Excel・サンプル固定長テキストを生成する（初回のみ）
2. **mapping.csv 更新** — `data/input`内の新規ファイル名からキーワード候補を拾い、`data/configs/mapping.csv`に未登録分を追記する（既定の設定ファイル名は要手動確認）。既存のmapping.csvを上書きする前に自動でタイムスタンプ付きバックアップ（`mapping.csv.bak_YYYYMMDD_HHMMSS`）を同じフォルダに作成する
3. **固定長テキスト → Excel 変換**
4. **Excel → 固定長テキスト 復元** — 復元後、続けて 5. の差分チェックも自動実行する
5. **差分チェック（入力 vs 復元後）のみ** — `data/input`の原本と`data/recreated_input`の復元後を、設定Excelの項目定義に沿って項目単位（バイト単位ではなく）で突き合わせ、値が変わった行・項目をログに出す。「特定の列だけ編集したつもりが、他の列やレコード構成まで変わっていないか」のダブルチェック用（行数が食い違う場合は行の増減の可能性として個別に警告し、項目比較は行わない）

00_ランチャーには「起動（GUI）」「起動（CUI）」の2アクションとして登録済み。

## 注意
- `data/`配下は実データが入るためGit管理外（`.gitignore`対象）。設定Excel・入力ファイルは各自の環境で用意する。
- Excel編集時に項目値前後の空白（パディング）情報は失われるため、値を変更せず往復させた場合を除き、元のバイト列と完全一致することは保証しない（区分コード・項目値そのものは完全に保持される）。
- 対象ファイルをExcel等で開いたまま変換・復元を実行すると、そのファイルだけスキップしてエラーログに出力し、他のファイルの処理は続行する。該当ファイルを閉じてから再実行すること。
- 変換・復元・差分チェックの実行時に、設定Excelの桁定義を検証して WARNING で通知する（処理は止めない）：フィールド範囲の重なり／フィールド間の未定義バイト（隙間）／開始位置・文字数が1未満／開始位置・文字数のセルが数値でない（その項目は無視）／レコード種別ごとの終端位置（想定レコード長）が種別間で不一致。
- 変換時は、行の実バイト長が設定Excelの想定レコード長と食い違う行を WARNING で通知する（設定の桁定義ミス、または想定と異なる形式のファイルの兆候）。復元時は、Excel上で編集した項目値がフィールドのバイト長を超えると切り捨てられ、該当行・項目・超過バイト数を WARNING で通知したうえでファイル末尾に「切り捨てN件」のサマリを出す（2バイト文字の途中では切らず、半端なバイトはスペースに置き換える）。
