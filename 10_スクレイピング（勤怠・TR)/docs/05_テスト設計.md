# 05 テスト設計（pytest）

## IT新人向け

### なぜテストを書くの？

プログラムを修正するたびに「壊れていないか」を手動で確認するのは大変です。
テストを書いておけば、コマンド1つで「全機能が動いているか」を自動確認できます。

```
手動確認：プログラムを起動 → 操作 → 目視確認 → 5分かかる
自動テスト：python -m pytest → 1秒で36件を確認
```

### pytest とは

Python のテストフレームワークです。
`test_` から始まる関数を自動で見つけて実行してくれます。

```python
# tests/test_config.py
def test_トップレベルキーがマージされる():
    base = {"a": 1, "b": 2}
    update = {"b": 99, "c": 3}
    config._deep_merge(base, update)
    assert base == {"a": 1, "b": 99, "c": 3}  # ← これが正しければ PASSED
```

`assert` は「これが正しいはず」という宣言です。
期待した値と違ったとき、テストが `FAILED` になります。

### テストの実行方法

```bash
# プロジェクトルートで実行
python -m pytest tests/ -v

# 結果をファイルにも保存
python tests/run_tests.py
```

### テスト結果の読み方

```
test_config.py::Test設定ファイルの読み込み::test_tr_optionsがリストとして読み込まれる PASSED
```

`テストファイル名 :: クラス名 :: テスト関数名` という形式です。
`PASSED` なら成功、`FAILED` なら失敗で詳細が表示されます。

### このプロジェクトのテスト構成

```
tests/
├── conftest.py           # 共通設定・フィクスチャ
├── test_config.py        # config.py のテスト（18件）
├── test_config_manager.py # config_manager.py のテスト（18件）
└── run_tests.py          # 結果をファイル保存するスクリプト
```

**テスト対象の選択基準：**

| 対象 | テストあり | 理由 |
|---|---|---|
| `config.py` | ○ | ロジックが複雑（ディープマージ・テンプレート） |
| `config_manager.py` | ○ | 主要機能（パターン追加）の保証が必要 |
| `gui.py` | ✗ | Tkinter はブラウザと同様に「起動」が必要で自動化コストが高い |
| `browser_utils.py` | ✗ | Selenium はブラウザが必要でユニットテスト不向き |

### フィクスチャ（共通セットアップ）

```python
# conftest.py
@pytest.fixture()
def project_root(tmp_path, monkeypatch):
    # テスト専用の一時フォルダにYAMLを作る
    (tmp_path / "config" / "modes" / "task_report").mkdir(parents=True)
    (tmp_path / "config" / "main.yaml").write_text(MAIN_YAML_CONTENT, encoding="utf-8")
    monkeypatch.chdir(tmp_path)  # カレントディレクトリを一時フォルダに変更
    return tmp_path
```

`project_root` フィクスチャを使うテストは、**実際のYAMLを一切触らずに動きます**。
テストが終わると `tmp_path` は自動で削除されます。

### monkeypatch の使い方

`monkeypatch` はテスト中だけ一時的に環境を変える pytest の機能です。

```python
# 環境変数を一時的にセット（テスト終了後に自動復元）
monkeypatch.setenv("CROWDLOG_EMAIL", "test@example.com")

# カレントディレクトリを変更（テスト終了後に自動復元）
monkeypatch.chdir(tmp_path)

# 関数をモックに差し替え（テスト終了後に自動復元）
monkeypatch.setattr("config.config.load_dotenv", lambda: None)
```

`monkeypatch` がなければ、テストのたびに環境変数や作業ディレクトリが変わってしまい、
他のテストに影響します。

### 良いテストの書き方

**1つのテストは1つのことだけを確認する**

```python
# NG: 1つのテストで複数のことを確認している
def test_add_pattern():
    manager.add_pattern(...)
    assert yaml_exists()       # ファイル確認
    assert main_yaml_updated() # main.yaml確認
    assert conf_reloaded()     # config確認 ← 別のテストに分けるべき

# OK: 目的を絞る
def test_パターンYAMLファイルが作成される():
    manager.add_pattern(...)
    assert (path / "abc.yaml").exists()  # これだけ

def test_main_yamlのtr_optionsに新エントリが追記される():
    manager.add_pattern(...)
    keys = [opt["key"] for opt in load_yaml("main.yaml")["menus"]["tr_options"]]
    assert "abc" in keys  # これだけ
```

## 上級者向け

### テスト設計の判断

#### なぜ関数名を日本語にしたか

```python
def test_パターンYAMLファイルが作成される(self):
def test_既存キーの重複追加はValueErrorになる(self):
```

英語関数名（`test_creates_pattern_yaml`）の場合、pytest の出力を読むには
「英語を日本語に訳す」という脳内変換コストがかかります。
日本語関数名にすることで、出力が **そのままドキュメント** になります。

```
Testパターン新規追加::test_パターンYAMLファイルが作成される PASSED
Testパターン新規追加::test_既存キーの重複追加はValueErrorになる PASSED
```

Python は Unicode 識別子をサポートしているため、日本語関数名は文法的に正しいです。

#### tmp_path + monkeypatch.chdir の理由

`config_manager.py` が `"config/main.yaml"` を相対パスで参照しているため、
テスト時のカレントディレクトリが `add_pattern()` の動作を左右します。

```python
# config_manager.py（ハードコードされた相対パス）
main_yaml_path = "config/main.yaml"
```

これを解決するアプローチが 2 つあります：

**A: monkeypatch.chdir（現在の実装）**
```python
monkeypatch.chdir(tmp_path)  # テスト中だけカレントを変える
```
- テスト側で制御する方法
- 本番コードを変更しなくていい

**B: pathlib で絶対パス化（本番コードの改善）**
```python
# config_manager.py を修正
ROOT = Path(__file__).parent.parent.parent  # src/config/ の3つ上
main_yaml_path = ROOT / "config" / "main.yaml"
```
- 本番コードが堅牢になる
- monkeypatch.chdir が不要になり、テストがシンプルになる

今の規模では A が正解ですが、B への移行コストも低いです。

#### テストカバレッジの考え方

#### run_tests.py の UTF-8 対策

Windows では `python -m pytest > output.txt` が cp932 でリダイレクトされ文字化けします。
`run_tests.py` で以下の対策を取っています：

```python
env = os.environ.copy()
env["PYTHONIOENCODING"] = "utf-8"  # pytest の出力を UTF-8 にする

result = subprocess.run(
    [sys.executable, "-m", "pytest", ...],
    stdout=subprocess.PIPE,   # バイト列で受け取る
    env=env,
)
output = result.stdout.decode("utf-8", errors="replace")  # 明示的にデコード

with open(output_file, "w", encoding="utf-8-sig") as f:   # BOM付きUTF-8で保存
    f.write(output)
```

`utf-8-sig` (BOM付き) にすることで Windows のメモ帳でそのまま開けます。
