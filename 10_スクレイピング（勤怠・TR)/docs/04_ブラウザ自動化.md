# 04 ブラウザ自動化（Selenium）

## IT新人向け

### Selenium って何？

Selenium は **Pythonからブラウザを操作する** ライブラリです。
まるで人間が操作しているかのように、Webページのボタンを押したり、
テキストを入力したりできます。

```
Python スクリプト
    ↓  指示を送る
Chrome ブラウザ（自動操作）
    ↓  Webサイトにアクセス
タスクレポートシステム
```

### 何ができるの？

このプロジェクトでやっていること：

1. ブラウザを起動する
2. タスクレポートのWebサイトを開く
3. ログインする
4. 対象のページを見つけてクリック
5. テキストボックスに値を入力する
6. ドロップダウンを選択する
7. 保存ボタンを押す

### WebDriver とは

Python が Chrome に指示を出す「通訳者」のことです。

```python
from selenium import webdriver

driver = webdriver.Chrome()   # Chrome を起動（この時点でブラウザが開く）
driver.get("https://example.com")  # URLを開く
driver.quit()                 # ブラウザを閉じる
```

### 要素を見つける方法

Webページの「部品」（ボタン・テキストボックスなど）を見つけるには、
HTML の属性名で探します。

```python
from selenium.webdriver.common.by import By

# name属性で探す（例: <input name="username">）
element = driver.find_element(By.NAME, "username")

# CSSセレクタで探す（例: <button class="submit-btn">）
element = driver.find_element(By.CSS_SELECTOR, ".submit-btn")
```

「name属性」は、HTMLソースを見てF12開発者ツールで確認できます。

## 中級者向け

### browser_utils.py の設計

このプロジェクトでは、Selenium の操作を `browser_utils.py` にまとめています。

```python
# Seleniumを直接使う（各Handlerにこれを書くとコードが重複する）
driver.find_element(By.NAME, "who_edit").send_keys("shimamura")

# browser_utils 経由（統一インタフェース）
browser_utils.input_text(driver, "name", "who_edit", "shimamura")
```

**なぜラップするのか？**

- 要素検索方法（`By.NAME`, `By.CSS_SELECTOR`...）をハンドラが意識しなくていい
- エラーハンドリングを1箇所に集中できる
- テスト時にこのモジュールだけをモックすれば、ブラウザなしでテストできる

### 待機戦略

Webページは非同期に描画されるため、**要素が出てくるまで待つ** 必要があります。

**暗黙的待機（implicit wait）**

```python
driver.implicitly_wait(10)  # 最大10秒、要素が現れるまで自動で待つ
```

`create_driver()` 内で設定しています。`find_element` のたびに自動で適用されます。

**明示的待機（explicit wait）**

```python
from selenium.webdriver.support.ui import WebDriverWait

# ページの読み込みが完了するまで最大30秒待つ
WebDriverWait(driver, 30).until(
    lambda d: d.execute_script("return document.readyState") == "complete"
)
```

`wait_for_page_load()` として `browser_utils.py` に定義してあります。
フォーム送信後にページ遷移があるケースで使います。

### JavaScript 経由の操作

通常の `send_keys()` や `click()` が失敗する場合、JavaScript で直接操作します。

```python
# テキストを JavaScript でセット（長文・非表示要素への入力に有効）
driver.execute_script("arguments[0].value = arguments[1];", element, text)

# JavaScript でクリック（要素が別要素の下に隠れている場合に有効）
driver.execute_script("arguments[0].click();", element)

# Changeイベントを発火（JS でセットした場合、手動発火が必要なことがある）
driver.execute_script(
    "arguments[0].dispatchEvent(new Event('change', {bubbles: true}));", element
)
```

`select_option_by_text()` で `dispatchEvent` を呼んでいるのはこのためです。

### セレクトボックスの操作

```python
from selenium.webdriver.support.select import Select

# value属性で選択（HTMLの value="shimamura" を指定）
Select(element).select_by_value("shimamura")

# 表示テキストで選択（画面に見えている文字で指定）
Select(element).select_by_visible_text("Shimamura学校")
```

YAMLに書く値をどちらにするかで使う関数が変わります。
本プロジェクトでは `value` 属性で管理しています。

## 上級者向け

### Selenium の信頼性問題

ブラウザ自動化は**本質的に不安定**です。以下の原因でよく失敗します：

| 原因 | 症状 | 対策 |
|---|---|---|
| ページ読み込みが遅い | `NoSuchElementException` | 暗黙的待機 / 明示的待機 |
| 要素が別要素に隠れる | `ElementClickInterceptedException` | `click_element_by_script()` |
| ネットワーク遅延 | タイムアウト | `wait_for_page_load()` |
| ページ構造変更 | 突然動かなくなる | セレクタの保守 |

**このプロジェクトの現状の対策：**

`browser_utils.py` の `is_element_present()` で要素の存在確認ができますが、
retry ロジック（失敗したら再試行）は現時点では実装されていません。

### Page Object Model (POM) との比較

現在の設計は **Handler が直接 `browser_utils` を呼ぶ** フラットな構造です：

```
TaskReportHandler
    ↓ 直接呼ぶ
browser_utils.input_text(driver, "name", "what_edit", title)
```

より大規模なプロジェクトでは **Page Object Model** を採用します：

```
TaskReportHandler
    ↓
TaskReportPage（ページを表すクラス）
    ↓ 内部で
browser_utils
```

```python
class TaskReportPage:
    def __init__(self, driver):
        self.driver = driver

    def set_title(self, title: str):
        browser_utils.input_text(self.driver, "name", "what_edit", title)

    def save(self):
        browser_utils.click_element(self.driver, "name", "send")
```

**POM のメリット：**
- ページのセレクタ変更が `TaskReportPage` だけの修正で済む
- Handler のコードが「何をするか」だけになり、「どうやるか」が隠蔽される

本プロジェクトの規模では現状でも十分ですが、
画面が増えたときに POM 化を検討するタイミングです。

### `context` dict によるパラメータ受け渡し

Handler は `context` 辞書でパラメータを受け取ります：

```python
context = {
    'schools_type': 'h',
    'environment_name': '',
    'school_defaults': config.CONF['school_specific_defaults']['h'],
    'common_defaults': config.CONF['common_defaults'],
    ...
}
```

この設計の**メリット**：新しいパラメータを追加しても Handler のコンストラクタを変えなくていい。

この設計の**デメリット**：どのキーが必要かコードを読まないとわからない。

型安全にするなら `TypedDict` や `dataclass` を使います。これは `01_プロジェクト構造.md` でも触れています。
