DirectoryOpenerApp クラス 解説資料

1. このクラスの役割（全体像）

DirectoryOpenerApp は、 設定ファイル（config.json）に基づいて ディレクトリ・URL・画面遷移用ボタンを動的に生成する Tkinter GUI アプリケーションです。

  • 設定ファイルを変更するだけで UI を差し替え可能
  • ページ切り替え型の GUI 構成
  • 設定編集 → UI 再構築まで一気通貫
コードを増やさず、設定でアプリを育てるための中核クラスです。

2. 依存関係と責務分離

DirectoryOpenerApp
 ├─ ConfigManager      : 設定の読み込み・検証
 ├─ ActionHandler      : ボタンクリック時の実処理（ディレクトリ/URLを開く等）
 ├─ UIBuilder          : configからウィジェットを組み立てる処理（旧 _create_widgets 系）
 ├─ SettingsEditor     : 設定編集UI
 ├─ theme              : sv_ttkダークテーマ・タイトルバー装飾（任意依存）
 ├─ constants (C)      : 定数・キー定義
 └─ Tkinter / ttk      : GUI 表示
UI ロジックと設定管理を明確に分離しているため、 GUI 側は「設定をどう描画するか」に専念できます。
2026-07時点の構成では、ウィジェット構築（旧 _create_widgets 系）は UIBuilder クラスへ、ボタンの実処理は ActionHandler クラスへ それぞれ委譲されています。DirectoryOpenerApp 自身はこれらを初期化して つなぎ合わせる「司令塔」役に専念します。

3. 初期化処理（__init__）の考え方


self.config_manager = ConfigManager()
self.config = self.config_manager.get_config()
if not self.config:
    master.destroy()
    return

設定が取得できない場合、即座にアプリを終了します。

「設定がない状態で GUI だけ動く」 という半壊状態を許さない、非常に堅実な設計です。

4. ウィンドウ設定（_setup_window）

ウィンドウタイトル・サイズ・リサイズ可否・アイコンなどを すべて設定ファイルから取得しています。

  • WINDOW_TITLE
  • GEOMETRY
  • RESIZABLE
  • WINDOW_ICON
見た目や振る舞いをコードから切り離し、 非エンジニアでも調整可能にしています。

5. スタイル管理（_setup_styles）


for style_name, options in styles_config.items():
    self.style.configure(style_name, **options)

ttk のスタイル定義を設定ファイル側に委ねることで、 UI テーマ変更をコード修正なしで実現しています。

6. ページ構造と動的生成（UIBuilder.create_widgets_content）

ページは Frame 単位で管理され、 設定ファイルの pages 定義から動的に生成されます。

この処理の実体は DirectoryOpenerApp ではなく UIBuilder クラス （ui_builder.py の create_widgets_content()）にあります。 DirectoryOpenerApp は self.ui_builder.create_widgets_content() を 呼び出すだけです。
  • ページ定義がなければ即エラー
  • 初期ページは設定で指定
  • ステータスバーは全ページ共通

7. エントリ生成のディスパッチ設計（UIBuilder._create_button）


if action == OPEN_DIRECTORY:
elif action == OPEN_URL:
elif action == SHOW_PAGE:
elif action == OPEN_PARAMETERIZED_URL:
action ごとに責務を分割することで、 機能追加時の影響範囲を最小化しています。 実装は UIBuilder._create_simple_action_button() （open_directory/open_url/show_page用）と UIBuilder._create_parameterized_url_entry() （open_parameterized_url用）に分かれています。

8. 動的スタイル生成の意図（UIBuilder内）

ボタンごとに背景色・文字色を変えられるよう、 スタイルを実行時に動的生成しています。

ttk の「スタイルはグローバル」という制約を、 カウンタ付きスタイル名（Dynamic.N.TButton）で回避しています。 ただし現在の sv_ttk ダークテーマでは、この動的スタイルの background（背景色）は反映されずforeground（文字色）のみ 反映される点に注意（config.jsonの明るい背景色パレットをそのまま流用すると 文字色だけが暗背景に残る）。

9. パラメータ付きURL機能の狙い

単なるリンク集ではなく、 入力値を埋め込んだURL生成を可能にしています。

  • TEXT / PULLDOWN に対応
  • URLテンプレート + format 方式
  • ユーザー入力をURLエンコード
業務システム・管理画面系ツールと非常に相性が良い構成です。

10. reload_ui の重要性

設定変更後に UI を完全再構築するための処理です。

  1. 全ウィジェット破棄
  2. 内部状態リセット
  3. 設定再読み込み
  4. UI 再生成
「設定変更＝再起動」を不要にし、 ツールとしての快適さを大きく向上させています。

11. ステータスバーの設計意図

成功・失敗を 色 + 文言で即時フィードバック。

  • 成功：青
  • 失敗：赤
messagebox 乱用を避け、 作業を中断させない UXを実現しています。

12. 設定画面との連携


SettingsEditor(
    self.master,
    self.config_manager,
    on_save_callback=self.reload_ui
)

設定保存後に UI を即リロードすることで、 設定 → 結果確認のループを高速化しています。

13. 設計思想まとめ

  • UI は設定の写像である
  • 壊れた状態では動かさない
  • 責務を細かく分ける
  • 変更コストを最小にする
