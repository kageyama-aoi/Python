33_CSV検証サポート 解説資料

1. このツール群の役割（全体像）

33_CSV検証サポート は、CSV/固定長テキストの 「分割」「改行付与」「差分比較」という3つの独立した検証作業を、 1つのランチャーGUI（launcher_gui.py）から実行・監視できるようにしたツール群です。

  • text_splitter — 巨大な区切りテキスト（CSV/TSV/TXT/DAT）を指定件数ごとに分割
  • fixed_length_formatter — 改行なしの固定長レコードファイルにバイト単位で改行を付与
  • diff_csv — 新旧2つの郵便番号CSVを比較し、差分と発行推定情報付きCSVを出力
3ツールはそれぞれCLIとして単独でも動く独立プログラムです。 ランチャーはそれらを subprocess.Popen で呼び出す「監督役」に徹しており、 分割・変換・比較のロジック自体はランチャーの外（各ツールの src/run.py）にあります。

4. 実行フロー（Run ボタンを押してから）

_on_run()
 ├─ panel.build_command()            → コマンド組み立て（失敗ならここでエラー表示して終了）
 ├─ _snapshot_dir(output_dir)         → 実行前の出力フォルダの状態を記録
 └─ threading.Thread(_run_process)    → 別スレッドでサブプロセス実行
      │
      │  proc.stdout を1行ずつ log_queue に流し込む（tkinterに直接触らない）
      ▼
 _drain_log_queue()（100msごとのafterループ、メインスレッド）
 ├─ 通常行 → _append_log()（色分けして表示）
 └─ 完了通知(_SENTINEL_RUN_DONE) → _on_run_finished()
      ├─ ログを logs/<tool>_<日時>.log に自動保存
      ├─ _detect_new_files()          → スナップショットとの差分で新規/更新ファイルを検知
      ├─ _show_run_summary()          → サマリー行を色分け表示＋点滅
      └─ panel.on_run_finished(new_files)  → ツール固有の後処理フック
ワーカースレッドは ログと完了通知を必ず log_queue 経由でメインスレッドに渡す という一本のルールを徹底しています。Tkinterウィジェットをスレッドから直接触らないことで、 実行中にウィンドウを閉じても壊れない設計です。
「出力ファイルの検知」は実行前後のスナップショット差分で行われます。 そのためツール側が既存ファイルを実行のたびに上書きする設計だと検知漏れが起きます （実際、3ツールとも出力は「実行ごとのサブディレクトリ」または「新規ファイル」になるよう 設計されており、この前提を満たしています）。

5. text_splitter のコアロジック（split_csv）

csv.reader / csv.writer によるストリーム処理で、 ファイル全体をメモリに載せずに rows_per_file 行ごとに分割します。

  • 区切り文字は delimiter が null なら先頭20行の , \t ; 出現数から自動判定（_detect_delimiter）
  • 出力は output_dir/<stem>_<YYYYMMDD_HHMMSS>/ という実行ごとのサブディレクトリに生成（再実行しても上書きされない）
  • 進捗は10,000行ごとに progress コールバックで通知（CLIはprint、GUIはキュー投入）
  • エラー時も finally で必ずログを書き出してから例外を再送出
SplitOptions（実行パラメータ）と config/config.json は1対1対応で、 from_config_file() で読み込み、validate() で検証します。 config/presets.json に名前付きで保存すれば、CLIから --preset 名前 でも GUIの「お気に入り」からでも同じ設定を呼び出せます。

6. fixed_length_formatter のコアロジック（format_fixed_length）

改行が一切ない固定長レコード（1レコード=record_bytesバイト）に、 バイナリストリーム処理（1MBチャンク）で改行を挿入します。

  • CP932の全角2バイトなど、バイト単位で区切ることを前提にしている（文字単位では区切らない）
  • 先頭のUTF-8 BOMは検出して読み飛ばす（レコード境界がズレないように）
  • record_bytes で割り切れない場合、末尾の半端バイトも出力しつつ警告を記録する（変換は止めない）
  • 先頭レコードを encoding（既定cp932）でデコードできるかを境界チェックとして記録する（boundary_ok）
「変換を止めずに警告だけ出す」という設計により、レコード長の指定が間違っていても 最後まで実行が終わり、結果とログから間違いに気づけるようになっています。 ランチャーの「折り返し確認」プレビューはこの境界チェックをGUI上で事前に試せる機能です。

7. diff_csv のコアロジック（postcode_diff）

新旧2つの郵便番号CSVから postcode 列を set として読み込み、 集合演算だけで差分を出します。 

only_in_old = set_old - set_new   # 廃止候補
only_in_new = set_new - set_old   # 新規追加
in_both     = set_old & set_new   # 継続

さらに新ファイルの各行に issue_info / issue_date_estimate / issue_note 列を追加した「発行推定情報付きCSV」も出力します。

他の2ツールと違い、入力ファイル名がソースコードにハードコードされています （postcode_diff.py の OLD_FILE / NEW_FILE）。 ランチャーの DiffCsvPanel はこの定義を正規表現で読み取って存在チェック表示するだけで、 ファイルを差し替えるにはソースコードを編集する必要がある点が他の2ツールと設計思想が異なります。

8. プレビューウィンドウ群の狙い

ウィンドウ役割
InputPreviewWindow入力ファイルの先頭10行とエンコードを表示し、has_header設定の判断材料にする。バックグラウンドで総行数・推奨分割行数も解析する
FixedLengthPreviewWindowレコード長を変えながら冒頭10レコードの折り返しをリアルタイムプレビュー。全レコードの境界チェック✓/✗付き
OutputDetailWindow実行で作成・更新された出力ファイルの一覧（サイズ・件数・エンコード）。解析はウィンドウを開いたときだけ実行
どのプレビューも「先頭の一部だけ読む」ことで巨大ファイルでも一瞬で結果が返るよう 徹底されています（_read_head_lines は64KBまで、 FixedLengthPreviewWindow は レコード長×10バイトまでしか読みません）。 重い処理（全行カウント）だけを別スレッドに逃がし、UIをブロックしないようにしています。

9. 出力ファイル検知とサマリー表示

実行前に _snapshot_dir() で出力フォルダの {相対パス: mtime} を記録し、 実行後に _detect_new_files() で比較することで「今回の実行で作成・更新されたファイル」だけを検知します。

  • text_splitter/fixed_length_formatter は「実行ごとサブディレクトリ」1階層下まで検知対象
  • サマリーは状態で色分け（実行中=青／出力あり=緑／出力なし=オレンジ）され、完了時に点滅して気づかせる

10. 自動クリーンアップ

起動0.3秒後にバックグラウンドで、LOG_CLEANUP_DAYS / OUTPUT_CLEANUP_DAYS （既定30日）より古いログ・出力ファイルを削除ではなくzip圧縮してから消します （logs/archive/、各ツールの <出力フォルダ>/archive/）。

実行ごとサブディレクトリはフォルダ単位で1つのzipにまとめられ、 新旧判定は「配下ファイルの最新更新日時」（_latest_mtime）で行われます。 archive/ 自体や desktop.ini 等の出力拡張子以外のファイルは対象外です。

11. ツール間連携（fixed_length_formatter → text_splitter）

「変換後、結果を text_splitter の入力にセットする」トグルがONの場合、 FixedLengthFormatterPanel.on_run_finished() が text_splitter パネルの入力欄に変換結果を直接セットし、 ツール選択を自動的に切り替えます。

「改行なし固定長 → 改行付与 → 行数分割」という典型的な作業の流れを1画面内で シームレスに繋ぐ導線です。パネル同士は self.app.panels 経由で 互いを参照できる設計になっています。

12. 設計思想まとめ

  • GUIはロジックを持たない（ロジックは常に src/run.py 側）
  • CLI・単体GUI・統合ランチャーの3経路から同じ結果が得られる
  • スレッドとUIは queue 経由でのみやり取りする
  • 重い処理（全件解析）は必要になるまで実行しない・別スレッドに逃がす
  • エラー時も必ずログを書き切ってから失敗を伝える
  • 削除ではなくzip化して、取り返しのつかない操作を避ける

13. 発展・改善余地

  • diff_csv の入力ファイル名をGUIから差し替え可能にする（現状はソース編集が必要）
  • text_splitter / fixed_length_formatter の「単体GUI」とランチャー内パネルのUIロジック重複の整理
  • プレビュー系ウィンドウ（Input/FixedLength）の実装パターンの共通化
